# Malicious Activities That Trigger Ransomware Alerts
# WatchRansom Detection System

## 1. Mass File Encryption (E - Encryption Ransomware)

Behavioral Pattern:
- High file_created count (encrypted files created)
- High file_read count (original files read before encryption)
- High directory_enumerated count (scanning directories for files)
- High apistats (cryptographic API calls)

Example Scenario:
Process scans C:\Users\Documents → 500+ files read
Process creates .encrypted versions → 500+ files created
Cryptographic API calls → high apistats
→ Classification: E (Encryption Ransomware)

## 2. File Locker Behavior (L - Locker Ransomware)

Behavioral Pattern:
- Moderate file_created count (locking files)
- High regkey_written count (disabling recovery options)
- High command_line length (complex ransomware commands)
- High dll_loaded count (loading malicious DLLs)

Example Scenario:
Process modifies registry to disable System Restore → high regkey_written
Process loads malicious DLLs → high dll_loaded
Process locks files with complex commands → high command_line
→ Classification: L (Locker Ransomware)

## 3. Zero-Day Anomalies (Autoencoder Detection)

Behavioral Pattern:
- Unusual reconstruction error (pattern doesn't match normal activity)
- Anomaly score ≥ 0.18
- Even if XGBoost classifies as goodware, autoencoder flags as suspicious

Example Scenario:
Normal pattern: 5 file operations, 2 registry reads
Anomalous pattern: 500 file operations, 0 registry reads
→ Autoencoder: High reconstruction error
→ Alert: ZERO-DAY THREAT

## 4. Specific Ransomware Signatures in Training Data

Your model was trained on these ransomware families:

Encryption Ransomware (E):
- WannaCry: Mass file encryption, SMB spreading
- Petya: MBR encryption, registry modifications
- Cerber: File encryption, process injection
- Locky: File encryption, network communication

Locker Ransomware (L):
- WinLocker: System lock, registry changes
- Police Ransomware: Registry modifications, DLL loading
- FileLocker: File locking, command obfuscation

## 5. Threshold-Based Triggers

Classification Threshold (0.85)
If max(P(E), P(L)) ≥ 0.85:
    → CRITICAL ALERT: RANSOMWARE DETECTED

Anomaly Threshold (0.18)
If reconstruction_error ≥ 0.18:
    → CRITICAL ALERT: ZERO-DAY THREAT

## 8. Normal Activities That Won't Trigger Alerts

These are safe activities your system correctly identifies as goodware:
- Opening documents (low file_read, low file_created)
- Installing software (moderate registry changes, but normal pattern)
- Web browsing (network connections, but normal pattern)
- System updates (registry changes, but legitimate process)
- File copying (moderate file operations, normal pattern)
- Running legitimate applications (normal behavioral patterns)

## 9. Edge Cases

False Positive Prevention
Your retrained model has 0 false positives on goodware because:
- Trained on 1869 real normal Windows activity samples
- Thresholds calibrated (0.85 classification, 0.18 anomaly)
- Feature aggregation over 30-second windows (reduces noise)

False Negative Possibility
Rare scenarios where ransomware might evade detection:
- Very slow encryption (below detection threshold)
- Fileless ransomware (no file operations)
- Memory-only attacks (no disk activity)
- Highly sophisticated evasion techniques

## 10. Detection Mechanisms

Primary Detection (XGBoost Classifier)
- Supervised learning on labeled ransomware samples
- Detects known ransomware families and patterns
- 3-class classification: G (Goodware), E (Encryption), L (Locker)
- Confidence threshold: 85%

Secondary Detection (Autoencoder)
- Unsupervised anomaly detection
- Trained only on normal Windows activity
- Detects zero-day and novel threats
- Reconstruction error threshold: 0.18

Combined Detection Logic
1. XGBoost classifies activity (G/E/L)
2. If ransomware confidence ≥ 85% → CRITICAL ALERT
3. Autoencoder calculates reconstruction error
4. If anomaly score ≥ 0.18 → ZERO-DAY THREAT ALERT
5. Both models must agree for highest confidence alerts

## 11. Alert Levels

CRITICAL
- Ransomware confidence ≥ 85%
- OR Anomaly score ≥ 0.9
- Immediate action required
- Process termination recommended
- System isolation recommended

WARNING
- Ransomware confidence ≥ 70%
- OR Anomaly score ≥ 0.7
- Monitor closely
- Investigate process behavior
- Consider quarantine

INFO
- Normal activity confirmed
- No action required
- System operating normally

## 12. Response Recommendations

Upon CRITICAL Alert:
1. Isolate affected system from network
2. Terminate suspicious process
3. Preserve memory dump for analysis
4. Check for lateral movement
5. Restore from backup if needed
6. Update detection rules

Upon WARNING Alert:
1. Monitor process behavior
2. Check process legitimacy
3. Review recent system changes
4. Verify user activity
5. Update monitoring if needed

## 13. Continuous Improvement

To improve detection accuracy:
1. Collect more normal activity data
2. Add new ransomware samples to training set
3. Retrain models periodically
4. Adjust thresholds based on false positives/negatives
5. Monitor detection performance metrics

## Summary

Your system triggers alerts when it detects:
1. Mass file operations (encryption/creation)

3. Cryptographic API usage (encryption)

5. High-confidence ransomware signatures (≥85%)

The dual-model approach (XGBoost + Autoencoder) provides defense against both 
known ransomware families and novel, unknown threats.
