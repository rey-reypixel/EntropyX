# Complete Project Documentation

## System Flow

### 1. Initialization Phase
main.py → load_config.json → start_monitoring.py
         ↓
    Initialize monitors (file, process, network, registry)
         ↓
    Load ML models (XGBoost, Autoencoder, Scaler)
         ↓
    Initialize event_collector and inference_engine

### 2. Monitoring Phase
Monitors run in parallel threads:
├── file_monitor.py    → Watches file system changes
├── process_monitor.py → Tracks process creation/activity
├── network_monitor.py → Monitors network connections
└── registry_monitor.py→ Detects registry modifications
         ↓
    All events → event_collector.add_event()
         ↓
    Events logged to monitor/logs/events.csv
         ↓
    Events sent to event_aggregator (30-second windows)

### 3. Classification Phase
Every 30 seconds or when min_events (10) reached:
    event_aggregator.get_aggregated_features()
         ↓
    Feature vector (12 behavioral features)
         ↓
    inference_engine.classify_aggregated()
         ↓
    ├── XGBoost classification (G/E/L)
    └── Autoencoder anomaly detection
         ↓
    alert_system.analyze_classification()
         ↓
    Generate alert if thresholds exceeded

## Parameters Analyzed (12 Behavioral Features)

The system aggregates events into 12 key features that match the training data format:

Feature              Description                          Source
file_read            File read/modify operations          file_monitor
file_created         File creation events                 file_monitor
regkey_written       Registry key modifications           registry_monitor
regkey_read          Registry key reads                    registry_monitor
apistats             API call statistics                   process_monitor
command_line         Command line argument length         process_monitor
directory_enumerated Directory enumeration count           file_monitor
dll_loaded           DLL loading activity                  process_monitor
tree_command_line    Process tree command lines            process_monitor
arguments            Number of process arguments           process_monitor
urls                 Network connections/URLs              network_monitor
proc_pid             Process identification count          process_monitor

## Event Types Tracked

### File Events
- created    - New file creation
- modified   - File content changes
- deleted    - File deletion

### Process Events
- created    - New process creation
- Command line arguments
- DLL loading
- CPU/memory usage

### Network Events
- connection - TCP/UDP connections
- Remote IP addresses
- Local/remote ports
- Connection status (ESTABLISHED, TIME_WAIT)

### Registry Events
- written    - Registry key modifications
- read       - Registry key reads

## ML Classification Logic

### XGBoost Supervised Classification
Input: 12 normalized features
↓
XGBoost model (3 classes)
↓
Output probabilities: [P(E), P(G), P(L)]
↓
Classification:
- If max(P(E), P(L)) ≥ 0.85 → Ransomware (E or L)
- Else → Goodware (G)

### Autoencoder Anomaly Detection
Input: 12 normalized features
↓
Autoencoder (trained only on goodware)
↓
Reconstruction error (MSE)
↓
Anomaly score = MSE / threshold
↓
If anomaly_score ≥ 0.18 → Anomalous (potential zero-day)

## Alert Levels

Level     Condition                              Action
CRITICAL  Ransomware confidence ≥ 85% OR        Immediate alert
          anomaly ≥ 0.9
WARNING   Ransomware confidence ≥ 70% OR        Caution alert
          anomaly ≥ 0.7
INFO      Normal activity confirmed             Informational

## Key Design Decisions

1. Time-window aggregation: Events are aggregated over 30-second windows to match 
   training data format (behavioral statistics rather than single events)

2. Dual-model approach: XGBoost for known ransomware patterns, autoencoder for 
   zero-day detection

3. Real-time processing: Monitors run in parallel threads, classification happens 
   every 30 seconds

4. Feature-based detection: Focuses on behavioral patterns rather than signature 
   matching

## Model Training Process

### Dataset Preparation
1. Collect normal Windows activity from event logs
2. Process events into 30-second aggregated windows
3. Merge with existing ransomware dataset
4. Create balanced dataset (2869 samples):
   - 1869 goodware samples
   - 800 encryption ransomware samples
   - 200 locker ransomware samples

### XGBoost Training
- Input: 12 behavioral features
- Output: 3-class classification (G/E/L)
- Accuracy: 98.43%
- Zero false positives on goodware test set

### Autoencoder Training
- Trained only on goodware samples
- Learns normal behavioral patterns
- Anomaly threshold: 0.18 (90th percentile of goodware reconstruction errors)
- Detects zero-day threats through reconstruction error

## Troubleshooting

### High False Positive Rate
- Increase classification_threshold in config.json
- Increase anomaly_threshold in config.json
- Collect more normal activity data and retrain models

### ML Components Failed to Load
- Ensure models are trained (check models/ directory)
- Verify all dependencies are installed
- Run with --no-ml flag for data collection mode

### Permission Denied Errors
- Run terminal/command prompt as Administrator
- Process and network monitoring need elevated permissions
